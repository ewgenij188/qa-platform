---
description: Интерактивное заполнение QA Portal daily report за сегодня
---

Проведи пользователя через заполнение daily report в QA Portal за СЕГОДНЯ. Весь диалог — по-русски. Работай через MCP `qa-portal` (инструменты `qa_portal_get_reports`, `qa_portal_meetings`, `qa_portal_save_report`) и Atlassian MCP (Jira).

Порядок строго такой:

0. Сначала проверь `qa_portal_get_reports` за сегодня. Если репорт уже есть — покажи его и спроси, перезаписать ли; если пользователь отказывается — завершай.

1. **Автоподбор задач с доски.**
   Перед вопросом пользователю запроси его задачи с доски CORE (board 421) через Atlassian MCP JQL:
   ```
   project = CORE AND assignee = currentUser() AND status in (3, 10142, 12696, 12699, 12697, 12700, 12701, 12698) ORDER BY status ASC
   ```
   ID статусов: 3=В работе, 10142=CODE REVIEW, 12696=DEV - READY FOR TEST, 12699=FEATURE - READY FOR TEST, 12697=DEV - IN TEST, 12700=FEATURE - IN TEST, 12701=FEATURE - READY FOR MERGE, 12698=DEV - READY FOR RELEASE.
   Запрашивай поля `summary` и `status`.
   - Если задачи найдены — покажи их списком (ключ, название, статус) и предложи пользователю выбрать одну или несколько (через `question` tool с `multiple: true`). Добавь опции «Ввести вручную» (если нужно указать другие задачи) и «Релиз» (включает режим релиза, шаг 2b). Пользователь может выбрать задачи из списка И «Релиз» одновременно.
   - Если задач не найдено — просто спроси: «Над какими задачами ты сегодня работал?»
   - В любом случае принимай номера в формате `CORE-1234` или просто `1234` (нормализуй к `CORE-1234`), списком через запятую/пробел.
   Если в ответе есть слово «релиз» или «release» (с номерами задач или вместо них) — включается **режим релиза** (см. шаг 2b).

2. Для каждой задачи получи название (summary) из Jira через Atlassian MCP (если уже получено на шаге 1 — повторно не запрашивай). Собери Daily Summary по шаблону:
   `Занимался задачами из спринта - <название задачи 1>, <название задачи 2>.`
   Если задача не нашлась в Jira — скажи об этом и уточни номер.

2b. **Режим релиза.** Определи номер текущего релиза: Atlassian MCP → `executeRead` с `name=getJiraProjectVersions`, inputs `{projectIdOrKey: "CORE", status: ["unreleased"], orderBy: "releaseDate", maxResults: 5}` — бери ближайшую unreleased версию (например `89.0`); покажи пользователю, какой номер взял. Если unreleased несколько или ни одной — уточни номер у пользователя.
   В Daily Summary добавь ВТОРОЙ строкой: `Занимался релизом CORE <номер>.` (если задач не было вовсе — это единственная строка).

3. Спроси через `question` tool: «Risks / Blockers — есть?» с вариантами «Нет» и «Да, опишу». Если «да» — попроси описать и запомни для questionId=2. Если «нет» — пропускай.

4. Спроси через `question` tool: «Incidents / Critical Bugs — есть?» с вариантами «Нет» и «Да, опишу». Если «да» — попроси описать и запомни для questionId=3. Если «нет» — пропускай.

5. Tasks / Time breakdown:
   a. Получи митинги за сегодня (`qa_portal_meetings`). Первая строка tasks всегда: `{task: "Митинги", timeSpent: "1h"}` — без jiraKey; если записей в календаре больше одной — поставь `"2h"`. Сообщи пользователю, сколько митингов нашёл и сколько времени поставил.
   b. Для КАЖДОЙ Jira-задачи из шага 1: отдельная строка `{task: <название из Jira>, jiraKey: <ключ>}`. Спроси у пользователя время по каждой задаче одним сообщением (например: «Сколько времени по CORE-1234, CORE-4291?»). Время передавай как написал пользователь («1ч 30м» допустимо — сервер понимает кириллицу), при необходимости нормализуй к виду `1h 30m`.
   c. **Режим релиза:** добавь строку `{task: "Релизом CORE <номер>", timeSpent: <остаток>}` — без jiraKey. Время считай сам, НЕ спрашивая: `8h − время митингов из п. a − сумма времени по задачам из п. b`. Покажи расчёт пользователю (например: «8h − 1h митинги − 2h CORE-4035 = 5h на релиз»). Если остаток ≤ 0 — скажи об этом и уточни распределение времени у пользователя.

6. Покажи итоговый черновик целиком: Daily Summary, Risks (если есть), Incidents (если есть), все строки tasks с временем. Спроси подтверждение через `question` tool с вариантами «Да, сохранить» и «Нет, поправить» (если поправить — уточни, что именно изменить).

7. Только после явного подтверждения вызови `qa_portal_save_report`: `date` = сегодня, `summary` = строка из шага 2, `answers` = риски/инциденты (если были), `tasks` = список из шага 5. Сообщи результат.
